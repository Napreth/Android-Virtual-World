# Android Virtual World

Android Virtual World (AVW) 是基于原版 QEMU、面向 Android 的虚拟化发行版，让用户能够修改虚拟 Android 设备的系统信息、模拟硬件输入，并通过脚本控制设备行为。

**Planning.**

## 项目目标

构建可独立运行的 Android 虚拟设备平台，提供完整的系统信息与硬件模拟功能，用于应用开发、自动化测试与系统研究。用户可以交互调整设备，也可以把配置和操作保存为场景，重复运行。

## 技术路线

以原版 QEMU 为基础，优先兼容 Android Studio 的 AVD 镜像，参考 Android Emulator 的镜像适配和 Cuttlefish 的硬件仿真实现。Cuttlefish 镜像兼容作为附加目标。

重点适配 AVD 镜像所需的启动配置、虚拟硬件、宿主通信和图形接口。Root 预计使用 Magisk，系统扩展通过 Magisk 模块实现，有需要时考虑采用内核模块。

## 模块规划

```text
qemu/           虚拟机运行、CPU、内存、加速、启动与快照
hardware/       共享虚拟硬件模型、设备状态与控制接口
interaction/    点击、滑动、手势、键鼠等输入交互
sysctrl/        系统信息与配置修改的 Magisk 模块
virtualenv/     设备配置、环境状态、时间线、场景与 DSL
gui/            桌面界面
cli/            命令行
```

`hardware/` 是 `qemu/`、`interaction/` 和 `virtualenv/` 的共同依赖，三个模块操作同一组虚拟硬件实例。`qemu/` 负责让设备参与虚拟机运行，`interaction/` 提交用户操作，`virtualenv/` 编排设备和环境变化。

## 功能规划

### 设备与镜像管理

统一管理虚拟设备、系统镜像和运行配置。用户可以从同一套配置创建多台设备，用快照保存运行状态，并在测试后恢复到指定状态。

- **设备管理**：创建、导入、克隆、导出、删除，以及启动、关闭、暂停和恢复。
- **运行配置**：CPU、内存、存储、显示、启动参数、端口和资源分配。
- **镜像与快照**：镜像导入、版本管理、设备独立补丁、快照保存与恢复、配置备份与回滚。

### Root 与系统定制

通过 `sysctrl/` 中的 Magisk 模块接收控制指令，修改 Android 系统信息和配置。

- **Root 启用**：为包含 `user` 镜像在内的 Android 系统开启或强制开启 Root。
- **系统信息**：品牌、制造商、型号、构建指纹、版本信息、Android ID、序列号及网络和电话标识。
- **系统环境**：语言、地区、时区、时间、系统属性、功能声明，以及应用管理、权限和应用操作控制（AppOps）。

### 虚拟硬件与外部环境

控制应用所处的硬件与外部环境，例如把视频作为摄像头画面、沿指定路线移动位置，或模拟断网和外设插拔。计划覆盖以下能力：

| 类别 | 计划功能 |
| --- | --- |
| 摄像头 | 前后摄像头、宿主摄像头、图片、视频、网络视频源、虚拟场景与输入源切换 |
| 麦克风与音频 | 宿主麦克风、文件和网络音频输入、静音、音量、音频路由与录制 |
| 位置 | 坐标、海拔、速度、方向、轨迹回放、定位漂移与信号丢失 |
| 运动与环境传感器 | 加速度、陀螺仪、磁场、姿态、步数、光照、距离、气压与温湿度 |
| Wi-Fi | 附近热点与扫描结果、网络名称（SSID）、接入点地址（BSSID）、信号、连接与切换 |
| 蓝牙 | 低功耗蓝牙（BLE）广播与扫描、虚拟外设与 GATT 服务、配对、连接与断开 |
| NFC | 标签靠近与离开、标签数据（NDEF）读写、卡模拟与错误事件 |
| 蜂窝与 SIM | 注册、信号、漫游、通话、短信、数据连接、SIM 插拔与多卡切换 |
| eSIM | 虚拟 eSIM 卡（eUICC）、测试运营商配置的管理与切换、配置下载流程研究 |
| 可信执行环境（TEE）与密钥服务 | 模拟密钥生成与存储、锁屏凭据验证，以及 KeyMint、Gatekeeper、Weaver 和 StrongBox 等接口 |
| 生物识别 | 指纹录入与验证、认证失败与锁定、人脸识别扩展 |
| 红外 | 红外发射参数、信号波形、发送记录与虚拟接收端 |
| 电源与热状态 | 电量、充电、电池信息、温度、低电量、待机与热状态 |
| 显示与输入 | 分辨率、DPI、刷新率、旋转、多屏、折叠姿态、触摸、键鼠、手柄、手写笔与震动 |
| USB 与存储 | 外设插拔、OTG、可移动介质、低存储空间与 I/O 异常 |
| 网络环境 | 断网、延迟、限速、丢包、DNS、代理与多设备网络 |

后续扩展方向包括多摄组合、深度相机、卫星定位（GNSS）原始测量、心率和超宽带（UWB）测距。

### 显示与交互

对 QEMU 的显示逻辑进行优化，虚拟显示器和图形渲染放在 `hardware/display/` 中。设备在后台运行时保留显示状态，用户可以随时打开、关闭或使用程序转发、录制桌面显示窗口，无需重启虚拟机。

`interaction/` 将点击、滑动、长按、多点触控和键鼠操作直接提交给虚拟输入设备。GUI、CLI 和 DSL 使用同一套交互能力。

### 运行时控制

在设备运行时调整硬件状态，触发蓝牙断连、SIM 插拔、传感器异常等事件，观察应用和系统的响应。配合操作日志、配置比较、导出与恢复，重现问题发生时的环境。

### 虚拟环境、设备配置与场景包

`virtualenv/` 统一管理设备配置和动态环境，将位置、运动、光照、无线信号等变化放在同一条时间线上。例如模拟设备走出室内时，Wi-Fi 信号减弱、光照增强，并切换到蜂窝网络。

设备配置（Device Profile）将镜像、Root 启用选项、系统身份、硬件配置与初始状态保存为可复用的设备模板，用于快速创建相同环境。计划支持导入导出、继承和版本管理。

场景包将设备配置与配套脚本、媒体素材、位置轨迹、虚拟外设和运行参数一并组织，方便分享完整测试场景、批量运行和复现问题。

### DSL 场景脚本

DSL 是描述设备行为的场景脚本，可以设置初始配置、按时间触发事件、等待某个条件，并自动检查结果（断言）。例如编排一段“沿路线移动 → 网络变弱 → 断网 → 恢复连接”的测试过程。

计划支持变量、条件、循环、子场景、多设备编排与执行报告。

初步采用 YAML/JSON 描述。以下示例设置初始位置和电量，再按时间触发低电量、断网并检查结果：

```yaml
device:
  name: lab-phone
  root: magisk

configure:
  battery:
    level: 80
  location:
    latitude: 22.1987
    longitude: 113.5439

scenario:
  name: low-battery-offline
  steps:
    - at: 5s
      set:
        battery:
          level: 20
    - at: 10s
      set:
        network:
          connected: false
    - at: 15s
      assert:
        path: battery.level
        equals: 20
```
